1. Keep sqlx. Axum already uses Tokio; rusqlite would make us own connection scheduling. SQLx itself moves SQLite's blocking calls onto a [worker thread](https://docs.rs/sqlx/latest/sqlx/sqlite/struct.SqliteConnection.html). Use a small pool, WAL, foreign keys, busy timeout, and short transactions. Compile checking requires query macros, committed `.sqlx` metadata, and [`cargo sqlx prepare --check`](https://docs.rs/sqlx/latest/sqlx/macro.query.html) in CI. Ordinary `query()` calls do not buy that guarantee. Neither driver removes SQLite's single-writer constraint.

2. Keep utoipa because the Svelte client and OpenClaw need a reliable contract. Its [schema derives and endpoint annotations](https://docs.rs/utoipa/latest/utoipa/) justify the ceremony. Allow schema derives in `den-core`, with HTTP annotations in the server. Generate TypeScript from the exported spec and check drift in CI. Include request/error types and explicitly export `Event`, which REST routes will not necessarily reference. OpenAPI does not specify our WebSocket protocol; document that separately. No Swagger UI needed initially.

3. Pick WebSocket for both clients. Typing and presence justify bidirectional traffic; keep durable writes on REST. Add heartbeat, bounded queues, reconnect backoff, and explicit resync after disconnect or lag. M1 can refetch authorized channel state, including edits/deletes, rather than promise durable event replay. `tail` must report gaps. Filter events by membership and close revoked sessions. The CLI needs a WebSocket dependency beyond its current ureq client; emit JSON lines for agents.

4. Local disk and a 1 GB cap are right. Chunking must support retry/resume, verify offsets and total size, finalize atomically, and clean abandoned temporary files. Reserve disk headroom; never buffer a whole upload. Authenticate range requests and implement HEAD, 206/416, Content-Range, and correct MIME types. Range serving cannot fix incompatible codecs. Target H.264/AAC MP4 with front-loaded metadata and `playsinline`; Apple's [Safari guidance](https://developer.apple.com/documentation/webkit/delivering-video-content-for-safari) supports H.264 MP4 and inline playback. Keep originals, offer download fallback, and test real gaming/iPhone clips before deciding on transcoding. Defer HLS. Test interrupted uploads and authenticated seeking on-device.

5. Try Tauri 2 first, but move the iOS feasibility test before M3, once text works. Tauri uses [WKWebView](https://v2.tauri.app/develop/plugins/develop-mobile/); sharing HTML does not prove call reliability. On a physical iPhone, test camera/mic permissions, Bluetooth routing, interruptions, locked-screen audio, reconnection, and large uploads. Failure of required call behavior should trigger SwiftUI plus LiveKit Swift. Define whether iOS screen broadcasting is required and test it separately; receiving a share proves nothing about broadcasting. The iMac builds it; a simulator cannot settle this decision.

6. Host networking for LiveKit is reasonable. Put signaling behind Caddy TLS; expose WebRTC media directly as [LiveKit documents](https://docs.livekit.io/transport/self-hosting/ports-firewall/). Current Caddy targets `localhost:7880` inside its bridge container, while LiveKit runs on the host. That route is broken by inspection. Give Caddy an explicit host-gateway upstream and prefer `rtc.<domain>` over a path prefix. Configure TURN for restrictive networks and plan its TLS port alongside Caddy. Pin LiveKit's version. The mounted YAML hardcodes `devkey/devsecret`; changing Den's environment alone will break token verification.

7. Keep invites and passwords. Bootstrap the first admin locally; make invites expiring and use-limited. Use Argon2id, login throttling, revocable opaque sessions, and Secure/HttpOnly/SameSite cookies. Protect cookie writes against CSRF and validate browser WebSocket origins, consistent with [OWASP guidance](https://cheatsheetseries.owasp.org/cheatsheets/WebSocket_Security_Cheat_Sheet.html). Store random bearer-token hashes and show secrets once. A token authenticates a user; it is not a user. Bots need stable identities, human owners, and revocation. Default bot access to member permissions. Define human-token impersonation explicitly and authorize DMs, attachments, and room tokens by membership.

8. Keep the simplicity rules. Replace the test-line-count warning with required behavior coverage, especially denied access and reconnects. Exempt cryptography and protocol handling from the 50-line dependency rule. Require generated client types, immutable applied migrations, and secret redaction. Allow one small public API error shape despite the blanket error-hierarchy warning. Treat 400 lines as guidance.

Other objections: `Id = String` does not enforce the promised time ordering; choose an ID format and pagination order. DM membership is absent. Replies, reactions, read state, search, and preferences need server work missing from M1. Compose has no Dockerfile, and `/health` cannot serve the SPA. Backups must include uploads and a restore drill. Delay link previews until we address SSRF.

I accept the ownership split, with Astra owning those M2 APIs too. Move upload acceptance into M1 and a reachable TLS deployment with backups into M2; friends cannot use localhost. Fable can mock the agreed generated contract. Use short branches/worktrees for concurrent work, reviewing shared types and migrations before merging. Implementation remains paused.
