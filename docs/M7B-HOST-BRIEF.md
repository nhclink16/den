# M7b brief: den-host, access grants, and the terminal plugin

Owner: Astra (host lane). Fable wrote this and reviews the result. Read `docs/DESIGN.md`, `docs/IDEAS.md`, `docs/M7A-NOTES.md` (the plugin surface you are extending), `docs/M6-NOTES.md`, `AGENTS.md`, and the client code the canvas plugin touched, before writing anything. Visual language unchanged: dim room, amber for what is live.

Three deliverables, in this order, each committed and working before the next:
1. **`den-host`**: a small Rust binary in `crates/den-host` that runs on a person's machine, dials out to Den, and exposes terminal sessions to people the owner has granted.
2. **Access grants**: a core permission model in the server and client. Requests and approvals are cards in chat.
3. **Terminal plugin**: the second plugin on the M7a surface, rendering a live PTY with Ghostty's web renderer, docked, expanded, and as a call tile.

Done when: Nicholas installs `den-host` on codexbox with one command and an invite code, opens `/terminal codexbox` in his self-DM, runs `herdr` inside it and drives his fleet, then posts the card into `#general`, m6_bob opens it and watches live with Nicholas's cursor and output, Nicholas grants m6_bob control from the tile, m6_bob types and it lands, Nicholas revokes and m6_bob's keystrokes stop within a second, and all of it works at https://denchat.app after `deploy/release.sh`.

## Non-goals for this brief
No file transfer, no screen control, no direct WebRTC path yet, no screen-state sync yet, no mobile-native terminal. Build the seams for the last two (below) and stop.

## 1. den-host
- `crates/den-host`, binary `den-host`, same workspace conventions. Dependencies: `tokio`, `tokio-tungstenite`, `portable-pty`, `den-core`. Runs as the logged-in user, never root.
- `den-host login <invite-code>` exchanges a one-time **host enrollment code** (see grants) for a host token stored at `~/.config/den/host.toml` mode 600 with the server URL, host id, and a human name defaulting to the hostname. `den-host run` connects to `wss://<server>/hosts/ws` with that token and stays connected with backoff. `den-host status` prints connection state. Ship a `den-host install` that writes a user systemd unit on Linux and a launchd agent on macOS that runs `den-host run` at login. Windows: `den-host install` registers a Scheduled Task at logon; ConPTY comes free with `portable-pty`. Test Linux for real, describe macOS and Windows steps in the notes and mark them untested if you cannot run them.
- Protocol over the host socket, binary frames, defined in `den-core` as `HostFrame`: `Open { session_id, cols, rows, shell? }`, `Input { session_id, bytes }`, `Resize { session_id, cols, rows }`, `Close { session_id }` from server to host; `Output { session_id, bytes }`, `Exited { session_id, code }` from host to server. Coalesce output at 16 ms. Flow control: the host stops reading the PTY when 1 MiB is unacknowledged, with `Ack { session_id, bytes }` from the server.
- Sessions persist on the host when the socket drops and reattach on reconnect; the server replays nothing, the client re-requests a screen refresh by sending a SIGWINCH-style resize nudge. Keep the last 256 KiB of output per session on the host so a reattaching viewer gets recent scrollback.
- A visible indicator: while any session has a viewer other than the owner, `den-host` prints a line to its own log and, on Linux with `notify-send` available, posts a desktop notification `nicholas is viewing your terminal` once per viewer per session. Best effort.
- **Seam for v2**: the transport between server and host is one trait, `HostTransport`, with the WebSocket implementation now. The direct WebRTC data channel path (`str0m`) implements the same trait later. The PTY output feed is one trait, `ScreenSource`, streaming raw bytes now; the `libghostty-vt` screen-state source implements it later.

## 2. Access grants (core)
- Tables `hosts` (`id`, `owner_id`, `name`, `token_hash`, `online`, `last_seen`) and `grants` (`id`, `host_id`, `grantee_id`, `capability` in `{terminal_view, terminal_control}`, `expires_at` nullable for standing, `created_by`, `created_at`, `revoked_at`). Migration `0005_hosts.sql`.
- `POST /hosts/enroll` (owner) → one-time enrollment code valid 10 minutes, shown once in Settings, Machines. `GET /hosts` lists the caller's machines with online state. `DELETE /hosts/{id}` unenrolls and kills sessions.
- Access requests are objects: kind `access_request`, created with `POST /hosts/{id}/requests` `{ capability, duration_minutes | standing }` by anyone who can see the owner (any member). The server posts the request card into the DM between requester and owner (create or reopen the DM). The owner answers with `POST /requests/{id}/decide` `{ allow: bool }`, which creates the grant and updates the object state so the card re-renders as allowed or denied for both. Agents use the same endpoints; a bot's request shows the bot badge on the card.
- The owner always holds every capability on their own hosts without a grant. Standing grants are listed in Settings, Access, with revoke. `DELETE /grants/{id}` revokes; the server closes affected sessions and rejects further input within one second.
- Sessions: `POST /hosts/{id}/sessions` (owner, or a `terminal_control` grantee) → creates a session object of kind `terminal` and posts its card in the channel the caller names, defaulting to the caller's self-DM. Viewing a session requires `terminal_view` or better on that host or being the owner. Session state carries `host_id`, `cols`, `rows`, `active_controller_id`, `viewer_ids`, `ended_at`. Only one controller at a time: the owner, or a grantee the owner promotes from the tile (`POST /sessions/{id}/controller { user_id | null }`). Everything else is `Event::TerminalOutput { session_id, bytes }` to viewers and client `terminal_input` frames from the controller, both over the existing socket as binary messages, coalesced. Cursor position is whatever the output stream implies; no separate cursor relay.
- Recording: when a session ends, the server writes the timestamped output stream as an upload attached to the session object (`recording_upload_id`), format is a simple newline-delimited `[ms, base64]` JSON, so the card can replay by feeding bytes to the same renderer. Cap recordings at 64 MiB and stop recording beyond that with a note in the state.
- Every grant, request, decision, session start, controller change, and revoke is a line in the audit table `access_log` and visible under Settings, Access, newest first, last 200.
- `den-core` types for all of it, OpenAPI regenerated, CLI: `den host list`, `den host enroll` (prints the code), `den access request <host> <view|control> [--minutes N | --standing]`, `den access grants`, `den access revoke <id>`, `den terminal open <host> [--in <room>]`, `den terminal write <session> <text>` for agents. Add a `## Machines and terminals` section to `skills/den/SKILL.md` with the request flow an agent must follow: ask, wait for the decision event, then act, never poll faster than every five seconds.
- Tests, human-scale: one integration test for the grant model (owner always allowed, view cannot type, control can, revoke stops input, expired grant denied, outsider 404) and one for enrollment code single use and expiry.

## 3. Terminal plugin (client)
- `apps/web/src/plugins/terminal/`, registered like the canvas: object kind `terminal` with `card`, `view`, `tile`; slash command `/terminal <machine>`; palette actions `Terminal on <machine>` for each of the caller's online machines. Also a second object kind `access_request` whose `card` is the Allow / Deny card described below. No `view` for it.
- **Renderer: Ghostty.** Use `ghostty-web` (libghostty-vt compiled to WebAssembly) as the terminal component, pinned. Load it lazily like tldraw. Fonts: bundle a monospace with the app, use `IBM Plex Mono` which Den already loads, no CDN. If ghostty-web cannot render Herdr's TUI correctly, stop and report with a screenshot; do not substitute xterm.js.
- **Card**: same frame as the canvas card, 320px. Top area shows the last screen as text on `var(--bg)` in 9px mono, faded, or a `terminal` glyph if nothing yet. Bottom row: eyebrow `terminal`, then `<machine name>` in the display face, and on the right the controller's avatar with an amber dot when the session is live, viewers' avatars after it. Ended sessions show `ended · 12 min` and a play icon; clicking replays the recording in the docked view with a scrubber.
- **Docked and expanded** exactly like the canvas: 45% height, drag handle, expand and close on a pill, one docked object at a time, Escape closes. The tile in calls is the same view, read-only unless you are the controller.
- **Control banner**: when someone other than the owner controls, a 28px bar across the top of the terminal reads `bob has control` in 12px with an amber left border, and a `Take back` button for the owner. When you are a viewer, typing does nothing and a faint `View only` label sits bottom-right; if you hold `terminal_control` you get a `Request control` button there instead, which pings the owner via a tiny inline prompt on their tile, `bob wants control · Give · Not now`, no chat card for that one.
- **Access request card** in the DM: `nicholas wants a terminal on bob-pc` with the capability and duration in the muted line, two buttons `Allow` (btn lit) and `Deny` (btn quiet). After a decision the buttons are replaced by `Allowed for 1 hour` or `Denied` in mono. Requests from bots show the badge. Expired requests read `Expired`.
- **Settings**: `Machines` (owner's hosts with online dots, `Add a machine` reveals the enrollment code once with the install one-liner, `Remove`), and `Access` (standing grants with revoke, then the audit log). Both between Voice and Plugins.
- **Keys**: everything goes to the terminal when it has focus, including Ctrl+K and the call shortcuts; Escape twice within 400 ms releases focus back to Den. Show `Esc Esc to leave` bottom-left on first focus, once per session.
- **Copy**: palette `Terminal on codexbox`. Offline machine in the palette: shown disabled with `offline`. Ended: `Session ended`. Denied request toast: `bob said not now.`

## Tailnet shortcut (do this in v1)
If the viewer's browser can reach the host directly, use it. `den-host` also listens on its Tailscale interface only, when one exists, on a random port, and reports that address to the server. The client tries a direct WebSocket to it first with a 700 ms timeout and falls back to the relay through Den. The direct socket authenticates with a short-lived session token minted by Den. Show a faint `direct` label bottom-right of the terminal when the direct path is in use, mono 10px.
