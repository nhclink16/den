Owner: Astra (canvas lane). Fable wrote this and reviews the result. Read `docs/DESIGN.md`, `docs/IDEAS.md`, `docs/M3-NOTES.md`, `docs/M6-NOTES.md`, `AGENTS.md`, then `apps/web/src/app.css`, `store.svelte.ts`, `call.svelte.ts`, `MessageItem.svelte`, `Composer.svelte`, `ChannelView.svelte` before writing anything. Match the visual language exactly: dim room, amber only for what is live.

This is the start of M7. Two deliverables: (1) one new core primitive, the **live object**, and a **minimal client plugin API**; (2) the **canvas plugin** built on tldraw as the first plugin, shipped in the default build behind an admin switch. Do not build a general plugin framework. Build exactly the surface the canvas needs, and keep it small enough that a second kind (a poll, a shared list) could be added in an afternoon.

Done when: someone types `/canvas raid layout` in `#plans`, a card appears in chat, two people on different machines draw on it and see each other's cursors and shapes within a second, an agent adds shapes with the CLI and they show up live, the card's thumbnail updates, and all of it is running at https://denchat.app via `deploy/release.sh`.

## Server: live objects
- Table `objects`: `id` (ULID), `channel_id`, `message_id` (nullable until the card is posted), `kind` (text, e.g. `canvas`), `name`, `state` (JSON text, the full current document), `version` (integer, increments per patch), `thumbnail_upload_id` (nullable), `created_by`, `created_at`, `updated_at`. Migration `0004_objects.sql`. Deleting the message deletes the object.
- `POST /channels/{id}/objects` `{ kind, name, state? }` → creates the object and posts a message in that channel authored by the caller with empty content and `objects: [Object]`. `Message` gains `objects: Vec<ObjectSummary>` next to `attachments`. `ObjectSummary` is everything except `state`.
- `GET /objects/{id}` → full object including `state`. `GET /objects/{id}/summary` → without state.
- `POST /objects/{id}/patch` `{ base_version, put: [record], remove: [id] }` → applies per-record last-writer-wins on top of the current state regardless of `base_version` (it is informational, used for the resync heuristic), bumps `version`, persists, returns the new version. Records are opaque JSON objects with an `id` string; the server does not understand tldraw. Reject patches over 1 MiB and states over 8 MiB with a clear error.
- `PATCH /objects/{id}` `{ name?, thumbnail_upload_id? }`.
- Events: `Event::ObjectPatched { id, channel_id, version, put, remove, author_id }` to everyone who can see the channel, excluding nothing (the author uses it to confirm). `Event::ObjectPresence { id, channel_id, user_ids }` when the set of people with the object open changes.
- Client events over the existing WebSocket: `{ type: "object_open", object_id }`, `{ type: "object_close", object_id }`, `{ type: "object_cursor", object_id, x, y, page_id }` relayed as `Event::ObjectCursor { id, user_id, x, y, page_id }` to others with the object open, never persisted, rate-limited to 20 per second per socket, dropped beyond that. Closing the socket closes all objects for that user.
- Access is the channel's access, same as messages. DM outsiders get 404.
- Admin switch: `GET/PUT /settings` with `{ canvas_enabled: bool }`, default true, admin-only write, in a one-row `settings` table. When off, object creation returns 403 `canvas_disabled` and the client hides the command.
- `den-core` gets `Object`, `ObjectSummary`, `ObjectPatch`, the new events, and `Settings`. Regenerate the client's `schema.d.ts` from `/openapi.json`.
- CLI: `den canvas create <channel> <name>` (prints the object), `den canvas get <id>` (prints state JSON), `den canvas patch <id> --file patch.json` (or `-` for stdin), `den canvas rename <id> <name>`. Document the tldraw record shapes an agent needs for a rectangle, an arrow, and a text label in `skills/den/SKILL.md` with one worked example, so an agent can draw without reading tldraw docs.
- Tests: one integration test for object access and patch (member ok, outsider 404, patch merges per record, version increments, delete-message cascades) and one for the admin switch. That is enough.

## Client: plugin surface
Create `apps/web/src/plugins/index.ts` exporting `registerPlugin` and a `plugins` registry with exactly these hooks:
- `objectKinds: { [kind]: { card: Component, view: Component, tile?: Component } }`: `card` renders inside a message, `view` renders docked or expanded, `tile` renders in the call grid.
- `slashCommands: [{ name, hint, run(ctx) }]` where `ctx` has the channel id and a `post` helper.
- `paletteActions: [{ id, label, hint, run }]`.
Core reads these in `MessageItem.svelte`, `Composer.svelte`, `Palette.svelte`, and the call grid. Plugins live in `apps/web/src/plugins/<name>/` and are imported once in `main.ts`. The canvas plugin is `apps/web/src/plugins/canvas/` and its tldraw chunk is loaded with a dynamic `import()` the first time a canvas opens, so the base bundle does not grow. tldraw is React: mount it with `react-dom/client` inside a Svelte component and unmount on destroy. Pin `react` and `react-dom` exact versions.

## Client: the canvas plugin
- **Slash command.** Typing `/` at the start of the composer shows a small popover above the box listing commands from the registry with their hints, `background: var(--bg-2)`, hairline border, 8px radius; arrow keys and Enter pick; Escape closes. `/canvas <name>` creates the object in the current room. Name defaults to `Untitled canvas`. Not offered in voice rooms or when the admin switch is off.
- **Palette action.** `New canvas in #<room>` when a room is active.
- **Card in chat.** 320px wide, `background: var(--bg-2)`, hairline border, `border-radius: var(--r-lg)`, overflow hidden. Top: 16:9 thumbnail area on `var(--bg-3)`, showing the thumbnail image or, if none yet, a faint tldraw-style dotted grid. Bottom row, 10px 12px padding: an eyebrow `canvas`, the name in `var(--display)` 15px, and on the right the avatars of people currently on it at 20px overlapping by 6px, with a 7px amber dot with glow before them when anyone is on it. Whole card is a button; hover raises the border to `var(--ink-3)`. Tooltip `Open canvas`.
- **Docked view.** Opening a card docks the canvas above the message list in the main column, the same pattern as the cam strip: header stays, the canvas takes 45% of the column height (min 260px), a 6px drag handle on the bottom edge resizes it (persist per object in localStorage), then the message list and composer. Top-right of the canvas, three 28px icon buttons on a `rgba(0,0,0,.45)` pill: expand, close. Expanded fills the main column below the header with a collapse button in the same place. Closing leaves the canvas live for others and returns to plain chat. Only one canvas docked at a time; opening another swaps.
- **In a call.** A docked canvas also appears in the strip and the grid as a tile with the same priority as a screen share (wide). Its `tile` component is the same view, read-only until clicked to focus.
- **Presence and cursors.** Use tldraw's collaborator cursor support: each remote user's cursor with their display name and a color derived from the same hue formula as `Avatar.svelte`. Send `object_cursor` at most 20 times per second, coalesced. Presence updates the card's avatar row for everyone in the room, even those who have not opened it.
- **Sync.** On open, `GET /objects/{id}`, load the state into a fresh tldraw store. Listen to the store's document changes, coalesce for 150 ms, and `POST /objects/{id}/patch` with the changed and removed records. Apply incoming `ObjectPatched` events from others through `store.mergeRemoteChanges`. On `resync` or after a gap, refetch the full state and reload it. Never send or apply instance or session records; document records only.
- **Thumbnails.** The client with the lowest user id among those present exports a PNG at 640px wide 10 seconds after the last change, uploads it through the existing chunked uploads API to the object's channel, and `PATCH`es `thumbnail_upload_id`. Cards render `thumbnail_url` from the summary. Nobody else exports.
- **Settings.** In Settings, a new `Plugins` section between Voice and Layout, admin-only: a switch `Canvas`, with the sentence `A shared drawing board anyone in a room can open. Uses tldraw.` Non-admins do not see the section.
- **Keys.** Escape in a docked canvas closes it when the canvas itself does not consume it. Everything else is tldraw's own.
- **Copy.** Card tooltip `Open canvas`. Empty name fallback `Untitled canvas`. Disabled error `Canvases are turned off on this server.` Palette action `New canvas in #general`.
- **Sizes.** Report the gzipped size of the base bundle before and after in the notes; the base must not grow by more than 5 KB, the canvas chunk can be whatever tldraw is.
