# Dictation brief: on-device speech to text in the composer

Two owners: `den-ios` (iMac) for iOS, `astra-web` (codexbox) for the web client, which also covers the Tauri desktop apps. Nothing touches the server. Audio never leaves the device. Reference if useful: T3 Code shipped this in `pingdotgg/t3code` (`apps/mobile`, via `@react-native-ai/apple`); do not copy code, the approach is obvious.

## Shared UX
- A mic button immediately left of the send button in the composer, same size and style as the attach button. Tap to start, tap to stop. While listening the button turns `accent` with a soft pulsing ring (1.2 s ease, disabled under reduced motion) and a small mono `listening` label appears where the typing indicator goes. Recognized text streams into the composer at the caret: partial results replace the in-progress segment, finalized text stays. Stopping leaves the text editable; nothing ever auto-sends. Existing text is preserved and dictation appends with a space. `Escape` or tapping elsewhere stops listening.
- First use asks for microphone and speech permission with the platform prompt. Denied: the button shows a tooltip or sheet `Den needs the microphone for dictation. Allow it in Settings.` and does nothing. Unsupported: the button is hidden, not disabled.
- Settings, Voice gets a `Dictation` group: language picker (defaults to the device language, list from the platform), a `Punctuation` switch where the engine supports automatic punctuation, and on web a `Voice model: 40 MB, downloaded` line with a `Remove` action.
- Copy: tooltip `Dictate`, while listening `Stop dictating`. Web download prompt: `Dictation runs on this device. Download the voice model (40 MB) once?` with `Download` and `Not now`.

## iOS (den-ios)
- iOS 26 `SpeechAnalyzer` with `SpeechTranscriber` for on-device streaming transcription, `AVAudioEngine` input, volatile results shown as partial text and finalized ranges committed. Fallback to `SFSpeechRecognizer` with `requiresOnDeviceRecognition = true` when the analyzer or its assets are unavailable; if neither supports the language on device, hide the button. `NSSpeechRecognitionUsageDescription` and `NSMicrophoneUsageDescription` strings in plain words. Handle the audio session so dictation and a LiveKit call cannot run at the same time: while in a call the button dictates into the composer using the call's mic without breaking the call audio route, or is hidden if that proves unstable; say which in the notes. Haptic on start and stop.
- Test on the physical iPhone: dictate a sentence, verify it lands in the composer, verify no network traffic to speech endpoints (Xcode network report or a simple airplane-mode run), screenshot listening state to `docs/shots/dictation-iphone.png`. Note in `docs/M5A-NOTES.md` under `## Dictation`.

## Web and desktop (astra-web)
- Whisper in WebAssembly via `@huggingface/transformers` (pinned) with `whisper-base` or `whisper-tiny.en` quantized, WebGPU when available else WASM, loaded lazily on first tap after the download prompt, model cached in the browser cache or IndexedDB. Chunk the microphone stream every ~2 s with a small overlap for streaming feel; finalize on stop. Keep it in a web worker so the UI never stalls. Bundle size rule from M7a applies: the base bundle may not grow more than 5 KB; everything else is a lazy chunk.
- In Tauri, the same code runs; verify WebGPU/WASM works in WKWebView on macOS and WebView2 on Windows; note WebKitGTK behavior on Linux honestly.
- Smoke: Playwright with `--use-fake-device-for-media-stream` and a fake audio capture file containing a spoken sentence (`--use-file-for-fake-audio-capture`), assert the composer receives text within 10 s, screenshots of the listening state at desktop and mobile widths to `docs/shots/dictation-web-*.png`. Release, verify on denchat.app, write `docs/DICTATION-NOTES.md`, post `[astra-web] dictation done` to fable.
