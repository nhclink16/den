# Den — merged design punch list

*49 findings from 7 lenses, collapsed to 42 items. Ordered within each group by what it costs a person using Den every day.*

## Fix now

**1. Message text has no measure cap, so prose runs 120–260 characters per line**
- **Where:** every channel, DM, and search hit — the surface people read all day.
- **Change:** `.text { max-width: 68ch }` on the message body and the search-hit body. Leave attachments, code blocks and embeds full-width. Settings already caps itself at 680px, so the project has already picked a number.
- **Files:** `apps/web/src/ui/MessageItem.svelte:112`, `apps/web/src/ui/Search.svelte:91`.

**2. `--ink-3` fails AA in all 16 shipped palettes while carrying real content**
- **Where:** offline member names and the "N here · M total" eyebrow, "admin" tag, message timestamps, composer placeholder, palette hints, and the *muted* mic/camera state in the call strip. ink3-vs-bg2 measures 2.66:1 to 3.47:1 across every half.
- **Change:** re-tune `ink3` in `themes.json` until ink3-vs-bg2 is ≥4.5:1 in all 16 halves, and stop using it for state: give `.person.off` ink2, and give CallControls `.muted` a real off-state colour plus the slashed glyph instead of a dimming — right now the mic state you most need to see is the least visible thing on screen.
- **Files:** `crates/den-core/src/themes.json`, `apps/web/src/app.css:41`, `apps/web/src/ui/Members.svelte:43`, `apps/web/src/ui/CallControls.svelte:39`, `apps/web/src/ui/MessageItem.svelte:111`, `apps/web/src/ui/Composer.svelte:158`.

**3. The scrim is mixed from `--ink`, so every dialog in a dark theme brightens the app instead of dimming it**
- **Where:** command palette, server switcher, mobile drawer, Add-server dialog — backdrop *and* panel shadow. `--ink` is #ece5d8 in Den dark, so the 45% scrim is 45% white and the 60px "shadow" is a cream halo. Den dark is the default. *(Reported independently by two lenses.)*
- **Change:** make the scrim direction-independent — `--scrim: color-mix(in srgb, #000 55%, transparent)` in both halves — and split `--shadow`/`--shadow-lg` out as a separate black-based token. Never use `--scrim` as a `box-shadow` colour.
- **Files:** `apps/web/src/app.css:9-12`, `apps/web/src/ui/Palette.svelte:78,82`, `apps/web/src/ui/Shell.svelte:116-119`, `apps/web/src/ui/AddServer.svelte:55`, `apps/web/src/ui/ServerSwitcher.svelte:35`.

**4. Every light theme's accent fails contrast, breaking the primary button, links, mentions and the focus ring**
- **Where:** Login "Come in", message links and @mentions, sidebar unread count, `:focus-visible` outline, call-tile speaking ring. Den light (one click away) is 2.87:1 — below even the 3:1 non-text floor, so keyboard focus becomes guesswork.
- **Change:** run the same ≥4.5:1 check `deriveHalf` already applies to *generated* halves over the hand-authored ones and darken until they pass (Den light needs roughly #9a5c12). Where the accent is a fill with `color: var(--bg)`, check the pair in both directions.
- **Files:** `crates/den-core/src/themes.json`, cross-check `apps/web/src/lib/theme-runtime.ts:36-37`; consumers `apps/web/src/app.css:31,35,59`, `apps/web/src/ui/Sidebar.svelte:120`, `apps/web/src/ui/CallTile.svelte:43`.

**5. Every per-message action is unreachable by keyboard**
- **Where:** the React / Reply / Edit / Delete hover toolbar. `.tools { display: none }` removes the buttons from the tab order, so the `:focus-within` reveal can never fire from a keyboard — 40 Tab presses in #general never reach them.
- **Change:** swap `display:none/flex` for `opacity:0; pointer-events:none` with `:focus-within { opacity:1; pointer-events:auto }`, or give `article.msg` a roving `tabindex="0"`. While there, add `aria-label="React"` — the "😶" text currently wins over `title`, so the button announces as "face without mouth".
- **Files:** `apps/web/src/ui/MessageItem.svelte:83,123,127`.

**6. Three text fields zero out the focus outline and put nothing usable back**
- **Where:** room-header search (border goes to a 1.2:1 grey), Settings "Find a setting" (no focus rule at all), Search page query (border only, no ring). Meanwhile `.field` and the composer use accent border + 3px `--lamp-glow`. Four treatments for one signal. *(Merged from Accessibility + Motion/polish + Cross-screen.)*
- **Change:** one shared rule in app.css — `:where(input, textarea, .input-shell):focus-visible { border-color: var(--lamp); box-shadow: 0 0 0 3px var(--lamp-glow) }` — and delete the three local `outline: 0` overrides.
- **Files:** `apps/web/src/app.css:35,65`, `apps/web/src/ui/ChannelView.svelte:100-101`, `apps/web/src/ui/Settings.svelte:278`, `apps/web/src/ui/Search.svelte:78-79`.

**7. The message column has five different horizontal gutters**
- **Where:** at 1440px the left edges land at 260 (call strip), 264 (composer), 268 (messages, day divider), 274 (header icon), 292 (h1); the hover toolbar overhangs the day-divider line. Everything is stacked, so the eye reads all five edges at once.
- **Change:** add a `--gutter` token (20px, 16px under 600px) and use it for `.head` padding-inline, `.msg` padding-inline, `.day`/`.start`/`.new` margins, `.composer` padding-inline, `.tiles` padding, `.grid-scroll` inset and `.tools { right }`.
- **Files:** `apps/web/src/app.css`, `ui/ChannelView.svelte:92`, `ui/MessageList.svelte`, `ui/MessageItem.svelte:2,28`, `ui/Composer.svelte:7`, `ui/CallView.svelte:5`, `ui/CallGrid.svelte:6,11`.

**8. Call-dock controls are 28px squares packed edge to edge, with Leave at the end and no hover feedback**
- **Where:** sidebar and mobile call dock. Measured at 390px: five buttons at x = 99, 127, 155, 183, 211 — literally zero gap — and `button:hover { background: var(--bg-3) }` is the same token as the dock's own background, so the fill is invisible. *(Merged from Accessibility + Motion/polish.)*
- **Change:** 40×40 minimum under `@media (pointer: coarse)` (or 28px visuals with a 44px `::after` hit box), `gap: 4px`, extra margin isolating Leave, and a surface-relative hover — `background: color-mix(in srgb, var(--ink) 8%, transparent)` — which reads on both the bg-3 dock and the bg-2 expanded toolbar.
- **Files:** `apps/web/src/ui/CallControls.svelte:35-37`, `apps/web/src/ui/CallDock.svelte:18`.

**9. Losing the connection is signalled only by a 7px dot changing hue — no words, no announcement, and it strobes under reduced motion**
- **Where:** sidebar brand row. "Reconnecting" exists only as a `title` tooltip (unreachable on touch); in Tide light the alarm colour (3.86:1) is barely stronger than the all-clear (3.70:1) and blinks to 0.3 opacity; the composer still says "Say something in #general". Under `prefers-reduced-motion` the reset overrides duration but not `animation-iteration-count`, so the dot cycles thousands of times per frame. *(Merged from Color, Accessibility, Copy.)*
- **Change:** render the banner slot Shell already uses for "Reconnecting to the call…" with a `role="status"` line: "You're offline. Den is trying to reconnect." Give the dot a real accessible name and a shape difference, raise the blink floor to 0.6, and guard the blink with `@media (prefers-reduced-motion: no-preference)` the way DictationButton already does.
- **Files:** `apps/web/src/ui/Sidebar.svelte:24,93-95`, `apps/web/src/ui/Shell.svelte:64`, `apps/web/src/app.css:77-79`.

**10. Every text input except two is under 16px, so iOS Safari zooms the page on focus and never zooms back**
- **Where:** composer (15px), room-header search (13px), Settings search (13px), Search page, Login. The workaround already exists in exactly two files. Den ships an iOS build.
- **Change:** set the floor once — `@media (pointer: coarse) { input, textarea, select { font-size: 16px } }` in app.css — and delete the two local overrides.
- **Files:** `apps/web/src/app.css:24,34`, remove `ui/Palette.svelte:85` and `ui/Appearance.svelte:325`.

**11. The `danger` button class is dead on every delete, so the only red button in Settings is the harmless one**
- **Where:** `.btn.danger` is declared *before* `.btn.quiet` at equal specificity, so every `class="btn quiet danger"` delete renders muted grey while "Log out" (`btn danger`) renders red. Deleting a room and its entire history looks exactly like "Save name" beside it.
- **Change:** add `.btn.quiet.danger { color: var(--ember) }` (or move `.btn.danger` after `.btn.quiet`), and drop `danger` from Log out.
- **Files:** `apps/web/src/app.css:61-62`, `apps/web/src/ui/Settings.svelte:197,246,249,257`.

**12. Destructive actions use three different confirmation patterns depending on the settings page**
- **Where:** Machines/Access use `<InlineConfirm>`; Rooms/Agents use the native `confirm()` dialog people click through by reflex; deleting a custom theme has no confirmation at all. The least destructive action gets the best guard.
- **Change:** route every destructive action through `<InlineConfirm>` — replace the three `confirm(...)` calls with it (action + the current confirm sentence) and wire ThemeCard's trash button through it too.
- **Files:** `apps/web/src/ui/Settings.svelte:58,100,104`, `apps/web/src/ui/Appearance.svelte:145`, `apps/web/src/ui/ThemeCard.svelte`, pattern at `apps/web/src/ui/MachineSettings.svelte:42,52`.

**13. A wrong password says "Authentication required", and the error line shoves the button out from under the cursor**
- **Where:** login card — the first interaction anyone has with Den. The raw server string for a dozen unrelated 401s is echoed verbatim, and the conditionally-rendered `<p>` drops the button ~34px at the exact moment someone is clicking it. Busy state is only `opacity: 0.5`. *(Merged from Copy + Motion/polish.)*
- **Change:** special-case 401 from `/login`: "That username and password don't match. Check for typos, or ask an admin to reset your password." Render the error paragraph always with `min-height: 1.4em` and `visibility: hidden` when empty so nothing moves; swap the label to "Coming in…" while busy and set `cursor: default` on the disabled state.
- **Files:** `apps/web/src/ui/Login.svelte:26,54-56,66`; server string at `crates/den-server/src/lib.rs:435-440`.

## Worth fixing

**14. Command palette is a dialog in name only**
- No `aria-modal`, no focus trap, no focus restore; the result list is a plain `<ul>` of buttons with no listbox/option roles and no `aria-activedescendant`, so arrowing changes the highlight silently and Tab walks out behind the scrim.
- **Change:** `aria-modal="true"`, trap Tab, restore focus on close; `role="listbox"`/`role="option" aria-selected` with stable ids and `aria-activedescendant` on the input.
- **Files:** `apps/web/src/ui/Palette.svelte:60,62-65`.

**15. Mobile settings tab strip never scrolls the active section into view**
- At 390px the strip shows 4 of 11 sections with the fourth clipped mid-word; on Account the active link sits 438px off-screen with `scrollLeft: 0`, so nothing looks selected and nothing hints at the rest.
- **Change:** on mount and on `section` change, `activeEl.scrollIntoView({ inline: 'center', block: 'nearest' })`; add `mask-image: linear-gradient(to right, #000 85%, transparent)` on the trailing edge.
- **Files:** `apps/web/src/ui/Settings.svelte:281`.

**16. Expanded call grid caps tile height at 0.8× column width, so video hugs the top of an empty pane**
- Two cameras occupy y 100–282 of a pane running to y ~900. Expand is the gesture for "show me people bigger" and it barely changes anything.
- **Change:** use `(height - 8) / rows` as the value and apply the `stepX * .8` cap only as a lower bound for overflowing layouts, or centre the canvas vertically when `rows * stepY < height`.
- **Files:** `apps/web/src/ui/CallGrid.svelte:36`.

**17. Image attachments reserve no space, so the conversation shoves itself down as pictures decode**
- `<img loading="lazy">` with no width/height or aspect-ratio; the stick-to-bottom effect only fires on `list.length`, so a late-loading image also drops you off the bottom of a live room.
- **Change:** wrap in a reserved-ratio box with a `var(--bg-3)` placeholder (thumbnails are capped 512×512, so 4/3 or square is safe) and re-run the stick scroll in an `onload` handler when `stickToBottom`.
- **Files:** `apps/web/src/ui/Attachment.svelte:17,28`, `apps/web/src/ui/MessageList.svelte:18-21`.

**18. Presence is colour-only and never announced**
- `aria-label` on a role-less `<span class="dot">` is discarded by assistive tech; offline members differ only by `--ink-3` text and a dimmed avatar.
- **Change:** `<span class="sr-only">online</span>` inside the avatar (or `role="img" aria-label`), and the same on Members rows so a row announces "nicholas, offline".
- **Files:** `apps/web/src/ui/Avatar.svelte:16`, `apps/web/src/ui/Members.svelte:34`.

**19. The blocked-audio banner is a bare button with no sentence**
- Both sibling banners carry explanatory text; this one gives a person sitting in silence an unexplained "Play call audio" button, so the obvious reading is that nobody is talking.
- **Change:** add "Your browser blocked the call audio." before the existing button.
- **Files:** `apps/web/src/ui/Shell.svelte:76`.

**20. The mobile sidebar drawer does not take focus, trap it, or close on Escape**
- After tapping Menu, focus is still on the Menu button; the next four Tab stops are controls behind the scrim; Escape does nothing.
- **Change:** `<aside tabindex="-1">` + `.focus()` on open, `role="dialog" aria-modal="true"`, `inert` on `.main`, Escape handling in Shell's `key()`, focus restored to Menu on close.
- **Files:** `apps/web/src/ui/Shell.svelte:32-38,58`.

**21. Settings headings are three sizes and two typographic treatments across sibling pages**
- Pane titles: 30px (Appearance), 26px (Settings, Voice), 24px (Machines) — the title visibly grows and shrinks as you click down the sidebar. Section headings: Appearance uses 15px/700 sentence case, five other files use an 11px uppercase mono `--ink-3` eyebrow, so the same rank reads as far weaker in Voice than in Appearance. *(Merged from Typography + Cross-screen, 3 findings.)*
- **Change:** delete the local `h2` rules in Appearance and MachineSettings and let one 26px rule govern; pick one section-heading treatment (the eyebrow wins on usage, 5 files to 1) and define it once in app.css, reserving `.eyebrow` for true field labels if you go the other way.
- **Files:** `apps/web/src/ui/Appearance.svelte:264,267`, `ui/MachineSettings.svelte:59`, `ui/Settings.svelte:282,283,144,178,184,189`, `ui/VoiceSettings.svelte:71,90`, `apps/web/src/app.css:44-50`.

**22. Navigation never says which room or settings section you are in**
- No `aria-current` anywhere in the tree; the only cue is a low-contrast `--bg-3` tint.
- **Change:** `aria-current={active ? 'page' : undefined}` on sidebar channel links, the gear link, and the settings TOC links.
- **Files:** `apps/web/src/ui/Sidebar.svelte:47,82`, `apps/web/src/ui/Settings.svelte:123`.

**23. `--line` never reaches 3:1, so inputs and buttons have no discernible edge**
- 1.34:1 to 1.56:1 across all 16 halves. The "Find a setting" field has no visible boundary at all.
- **Change:** split the token — keep the current value for hairline panel dividers, add `--line-strong` at ≥3:1 vs bg for anything bounding an interactive control (`.field`, `.btn`, `.rx`).
- **Files:** `apps/web/src/app.css:54,62-64`, `crates/den-core/src/themes.json`, `apps/web/src/ui/Shell.svelte:110-112`.

**24. The Compact density setting never touches line-height, so it saves about 6%**
- `--density` is used in four places, all padding and margin; leading is pinned at 1.45 and is the 43.5px of a ~48px message block.
- **Change:** add `--leading` beside `--density` (1.35 compact / 1.45 comfortable) and use `line-height: var(--leading)` on `.text`.
- **Files:** `apps/web/src/lib/theme-runtime.ts:57`, `apps/web/src/ui/MessageItem.svelte:98,112`.

**25. The reduced-motion reset speeds animations up instead of stopping them**
- The block overrides duration but not `animation-iteration-count`, so infinite loops run thousands of cycles per frame. (The one current offender is the connection dot, item 9.)
- **Change:** add `animation-iteration-count: 1 !important` and `scroll-behavior: auto !important` to the block.
- **Files:** `apps/web/src/app.css:77-79`.

**26. Twenty-two hardcoded radii ignore the theme's own Corners setting**
- Pick Sharp and the composer buttons, slash menu and every call control keep 6–8px corners next to 2px panels; pick Round and they stay square.
- **Change:** `var(--r)` for controls and chips, `var(--r-lg)` for panels and menus, `calc(var(--r) - 2px)` where a nested control genuinely needs to be smaller.
- **Files:** `ui/Composer.svelte:143,144,159,170`, `ui/MessageItem.svelte:128`, `ui/CallControls.svelte:32,36`, `ui/CallTile.svelte:47,54`, `ui/CallView.svelte:29,34`, `ui/CallGrid.svelte:101`, `ui/DictationButton.svelte:83,91`, `ui/CallLayoutTile.svelte:77,78,82`.

**27. Theme previews hardcode px type inside a fluid card, and show the wrong font**
- `font-size: 5.2px` on a resizing card: on a phone the wordmark clips to "de", the headline wraps, the composer row falls out of frame; on the 2.3×-wider scheme cards the same type reads as a speck. `container-type: inline-size` is declared but no `cqw` unit is used. Separately, `.preview` hardcodes `system-ui` for body text, so Terminal and Paper preview identically even though the themes ship Source Sans, JetBrains Mono, Atkinson and others. *(Merged from 2 Typography findings.)*
- **Change:** express type and fixed dimensions in `cqw` (`.preview` 4.2cqw, `.brand` 5.6cqw, `.lines b` 4.5cqw, avatar 9cqw); extend props to take the full `ThemeFonts` and apply `body` to `.preview` and `mono` to the composer placeholder.
- **Files:** `apps/web/src/ui/ThemePreview.svelte:6,16,38,39,45,52,54`, `apps/web/src/ui/ThemeCard.svelte:33`, `apps/web/src/ui/Appearance.svelte` (scheme cards).

## Systemic, not local

These are the ones where fixing the instance leaves the cause in place. Worth doing first inside their group, because several punch-list items collapse into them.

- **Missing type-scale tokens.** app.css defines tokens for colour, radius and density but none for type size, and `ui/` already holds 24 distinct `font-size` values — four sizes for one heading rank, three for adjacent list bodies, plus one-off 12.5px and 10.5px. Add `--text-xs/sm/base/lg/xl` and convert. Fixes items 21, 36 and stops the drift. *(`apps/web/src/app.css:24`)*
- **Missing `--gutter` token.** Five edges in one column exist because each component picked its own padding. Item 7 only holds if the token lands. 
- **`--scrim` / `--shadow` are derived from `--ink`, which is semantically wrong.** A scrim is a darkener, not an ink tint; deriving it from ink guarantees it inverts in dark mode. Item 3 is the symptom.
- **`--line` carries two jobs at one value.** Hairline divider and interactive-control boundary have different contrast floors; one token cannot serve both. Item 23.
- **Hand-authored theme halves were never held to the contrast rule the code enforces on generated ones.** `deriveHalf` checks accent ≥4.5:1 for user themes; the 16 shipped halves in `themes.json` skipped it, which is why items 2 and 4 are 16-way failures rather than one-off mistakes. Run the existing check over `themes.json` in CI.
- **No motion tokens and effectively no transition layer.** 40 hover rules, 6 transitions. Item 38 is a token problem, not 40 component problems.
- **Hardcoded radii mean the Corners setting only half works.** 22 sites bypass `--r`; any new component will too unless the lint/convention exists. Item 26.
- **No shared primitives for four recurring patterns:** a section-heading class (3 local `h3`/`h2` rules, item 21), a searchbox (3 implementations, items 6 and 48), a settings list row (3 systems, item 47), a segmented control (2, item 46), and an avatar stack (2, item 45). Each divergence is a new component reinventing a thing that already exists twice.
- **Accessibility is per-component rather than in the primitives.** `aria-current` appears nowhere; presence is drawn without text; focus is styled per file; the palette and drawer each hand-roll dialog behaviour without modality. Items 5, 6, 14, 18, 20, 22 are one absence repeated — a shared focus rule, an `sr-only` utility, and one dialog wrapper (focus move, trap, Escape, restore, `inert`) would close most of them at once.
