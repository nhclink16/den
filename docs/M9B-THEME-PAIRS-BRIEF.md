# M9b brief: every theme gets a light and a dark half

Owner: Astra. Follow-up to M9; read `docs/M9-NOTES.md` and `docs/THEMES.md` first. Fable's original brief only authored two light palettes. The model changes to T3's: a **theme is a family** with both appearances, and Mode picks which half is shown. Nine families, eighteen palettes, all authored below; use them exactly.

Done when: Settings, Appearance shows one grid of nine family cards, each card previews both halves, picking a family sets both, Mode chooses light, dark, or system, the editor edits both halves with a Light/Dark tab, existing custom themes migrate, and denchat.app runs it.

```
Theme { id, name, light: ThemeColors, dark: ThemeColors, fonts, radius, density }
Appearance { mode: "light"|"dark"|"system", theme: id, custom_themes: Theme[] }
```

Migration `0008_theme_pairs.sql` rewrites stored appearance JSON: `theme` becomes the family of the previous `dark_theme` (fall back to `light_theme`, then `den`); custom themes with one half get the other half generated by the derivation rule below, flagged `generated: true` so the editor can mention it. Keep the 12-theme, 16 KiB limits and the contrast check for both halves of every family.

The former `den-light` id is retired; it is the light half of `den`. Default `theme: den`, mode `system`.

## Derivation rule for a missing half (custom themes only)
Given one half, produce the other by: swapping ink and bg lightness in OKLCH while keeping hue and chroma (bg ↔ ink, bg2 ↔ ink2, bg3 ↔ ink3), keeping `line` at 12% lightness offset from the new bg, and keeping accent/success/danger hues with lightness adjusted to pass 4.5:1 against the new bg. Never use it for built-ins; they are authored above.

## Settings, Appearance
- Mode segmented control stays. Below it, one grid of nine cards. Each card is the mini wireframe split diagonally: top-left half in the light palette, bottom-right in the dark, a thin `line`-colored diagonal between. Name under the card in the family's display font. Selected card has the check. In light or dark mode, the corresponding half is emphasized by dimming the other to 70%.
- Editor gains a `Light · Dark` tab above the color rows; edits apply live to whichever half is active on screen, and switching Mode while editing previews the other half. A `Copy from dark` / `Copy from light` link fills one half from the other via the derivation rule. Custom cards render both halves like built-ins.
- Copy: family cards have no eyebrow; custom ones keep `custom`. Generated-half hint under the editor tab: `Generated from the dark half, adjust to taste.`
